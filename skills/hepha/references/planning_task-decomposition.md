# 任务拆解指南

把需求按用户可观察行为拆成可独立验证、审查、沉淀和提交的垂直切片。

## 拆解顺序

1. 从 Spec 的场景和完成条件提取任务。
2. 为每个任务分配稳定 ID、Spec 引用和 Given/When/Then 验收条件。
3. 标记真实技术依赖，拒绝按文件顺序伪造依赖。
4. 高风险和高不确定性前置。
5. 为行为任务声明测试命令。
6. 判断是否需要形成个人资产。
7. 运行 `hepha-cli.js validate`。

## 最小任务判断

出现任一信号时继续拆分：

- 预计超过一个可审查循环。
- 触碰三个以上无关模块。
- 包含多个独立行为场景。
- 验收条件不能由一个聚焦测试或验证步骤覆盖。
- 一部分失败会阻塞其他可独立交付的价值。

## Ready Queue

任务为 `todo` 且所有 `depends_on` 任务为 `done` 时才可启动。优先选择高风险、能解锁后续任务或最早产生用户价值的任务。

完整字段和示例见 `runtime-schema.md`。
