# 进度可视化指南

## 用途

本文件定义 `.hepha/progress.md` 的格式规则。实际模板见 `templates/progress.md`。

## 文件结构

`progress.md` 包含：

1. **头部信息**：需求、时间、负责人
2. **进度概览**：进度条、状态汇总、依赖图
3. **循环历史**：每轮计划、执行、检查、审查、summary 路径
4. **风险日志**：阻塞和缓解措施
5. **完成总结**：需求完成后填写

## 进度条格式

```text
总体进度：[████████░░] 80% (4/5 个任务完成)
```

规则：

- `█` 表示已完成部分。
- `░` 表示剩余部分。
- 总宽度 10 个字符。
- 同时显示百分比和完成数。

## 状态值

| 中文状态 | state 值 |
|----------|----------|
| 已完成 | `done` |
| 进行中 | `doing` |
| 待执行 | `todo` |
| 阻塞 | `blocked` |
| 跳过 | `skipped` |

## 状态汇总表

```markdown
状态汇总：

| 状态 | 数量 | 任务 |
|------|------|------|
| 已完成 | 4 | TASK-001, TASK-002, TASK-004, TASK-005 |
| 进行中 | 1 | TASK-003 |
| 待执行 | 0 | - |
| 阻塞 | 0 | - |
```

规则：

- 列出真实任务 ID。
- 空类别写 `-`。
- 每轮结束后更新。

## 依赖图格式

使用 ASCII 表达依赖：

```text
TASK-001 (done) --> TASK-002 (done) --> TASK-003 (doing)
```

分支示例：

```text
TASK-001 (done) --> TASK-002 (done)
     |
     +------------> TASK-003 (done)
     |
     +------------> TASK-004 (todo)
```

## 循环记录格式

每轮记录应包含：

```markdown
### Loop #[N] - TASK-[XXX]：[任务标题]

**时间**：[ISO 时间]
**状态**：[已完成 | 进行中 | 阻塞]
**负责人**：[person]
**Commit**：[hash]
**Summary**：`.hepha/summary/YYYY-MM-DD/person/TASK-XXX.md`
**重试次数**：[N]

**计划**

- 选定任务：TASK-[XXX]
- 预计文件：[列表]
- 预计检查：[列表]
- 预计浏览器验证：[说明]

**执行**

- [本轮做了什么]

**检查结果**

- [命令]：[结果]

**审查结果**

- [验证内容和证据]

**变更文件**

- [file path]（新增/修改/删除）
```

## 自动更新规则

每轮结束后：

1. 更新进度条。
2. 更新状态汇总表。
3. 刷新依赖图。
4. 追加循环记录。
5. 写入本轮 summary 路径。

任务完成时，将状态从 `doing` 改为 `done`；阻塞时改为 `blocked` 并写入风险日志。

## 风险日志格式

```markdown
| 日期 | 任务 | 风险 | 缓解措施 | 状态 |
|------|------|------|----------|------|
| 2026-05-30 | TASK-001 | 外部服务不稳定 | 增加重试和降级 | 已缓解 |
```
